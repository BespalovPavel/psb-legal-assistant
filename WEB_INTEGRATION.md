# Руководство по интеграции фронтенда с API PSB Legal Assistant

Данный документ описывает протокол взаимодействия клиентского интерфейса (SPA / Web UI) с бэкендом PSB Legal Assistant.

---

## 1. Архитектурный принцип: Сервер — единственный источник истины

- **Фронтенд не хранит состояние диалогов как основное хранилище.** Вся история чатов, сообщений и привязанных источников персистентно сохраняется на сервере в PostgreSQL.
- Локальное состояние (например, Redux/Pinia/Zustand) используется исключительно в роли временного кэша и оптимистичного UI.
- При перезагрузке страницы или смене диалога актуальное состояние всегда запрашивается с сервера.

---

## 2. Навигация и список диалогов (Сайдбар)

- **Запрос списка чатов:** `GET /api/chats`
- **Ответ:**
  ```json
  [
    {
      "chat_id": "b3e0c7a1-8d2b-4fa8-a129-c456f9e8a712",
      "title": "Согласование договора с ООО «Северный Склад»",
      "updated_at": "2026-11-15T18:40:00+00:00",
      "last_message": "По договору аренды № А-08/2024..."
    }
  ]
  ```
- **Создание нового чата:** `POST /api/chats` с телом `{"title": "Новый чат"}` (поле `title` опционально). Ответ `201 Created` возвращает `{ "chat_id": "...", "title": "..." }`. После создания добавьте диалог в сайдбар и переключите активный экран.
- **Удаление чата:** `DELETE /api/chats/{chat_id}`. При успехе возвращает `{"status": "deleted"}`.

## 3. Просмотр и рендеринг диалога

- **Получение истории диалога:** `GET /api/chats/{chat_id}`
- **Ответ:**
  ```json
  {
    "chat_id": "b3e0c7a1-8d2b-4fa8-a129-c456f9e8a712",
    "title": "Согласование договора",
    "messages": [
      {
        "id": 1,
        "role": "user",
        "content": "Какой порядок возврата помещения при расторжении?",
        "created_at": "2026-11-15T18:41:00+00:00",
        "sources": []
      },
      {
        "id": 2,
        "role": "assistant",
        "content": "По договору аренды № А-08/2024 арендатор обязан вернуть помещение по акту приема-передачи...",
        "created_at": "2026-11-15T18:41:03+00:00",
        "sources": [
          {
            "doc_id": "dogovor-arendy-a-08-2024",
            "chunk_id": "dogovor-arendy-a-08-2024:p-6-3",
            "doc_title": "Договор аренды А-08-2024 Северный Склад",
            "path": "п. 6.3",
            "snippet": "6.3. При прекращении настоящего Договора Арендатор обязан вернуть Арендодателю Имущество по акту..."
          }
        ]
      }
    ]
  }
  ```

### Правила отображения сообщений
1. **Порядок:** сообщения рендерятся строго в порядке получения из массива (хронологически по `created_at` и `id`).
2. **Формат ответа ассистента:** рендерить как **чистый текст (plain text)** с сохранением переносов строк (`white-space: pre-wrap; font-family: inherit;`). Не использовать Markdown-парсеры.
3. **Чипы источников:** под каждым ответом роли `assistant` отображаются кликабельные чипы источников из массива `sources`.
   - Текст на чипе: `{doc_title} • {path}`.
   - **Запрет внутренних меток:** технические заголовки вида *"ДОКУМЕНТ #1"* или *"документ №2"* пользователю **не показывать**. Показывать только официальное наименование документа и конкретный пункт/статью (`path`).

## 4. Модальное окно просмотра фрагмента (Чанка)

При клике пользователя по чипу источника:
1. Выполните запрос: `GET /api/chunks/{chunk_id}`.
2. Ответ:
   ```json
   {
     "chunk": {
       "chunk_id": "dogovor-arendy-a-08-2024:p-6-3",
       "doc_id": "dogovor-arendy-a-08-2024",
       "ord": 12,
       "path": "п. 6.3",
       "section": "6. Возврат помещения",
       "text": "6.3. При прекращении настоящего Договора Арендатор обязан вернуть...",
       "note": null,
       "is_heading": false,
       "prev_id": "dogovor-arendy-a-08-2024:p-6-2",
       "next_id": "dogovor-arendy-a-08-2024:p-6-4"
     },
     "document": {
       "doc_id": "dogovor-arendy-a-08-2024",
       "title": "Договор аренды А-08-2024 Северный Склад",
       "status": "действует",
       "file": "документы компании__Договор аренды А-08-2024 Северный Склад.txt"
     }
   }
   ```
3. **Элементы модального окна:**
   - **Хлебные крошки:** `{document.title} / {chunk.path}`.
   - **Тело фрагмента:** полный текст карточки `chunk.text`.
   - **Кнопки навигации:**
     - `« Предыдущий фрагмент` — активна, если `chunk.prev_id != null`; по клику загружает `GET /api/chunks/{chunk.prev_id}`.
     - `Следующий фрагмент »` — активна, если `chunk.next_id != null`; по клику загружает `GET /api/chunks/{chunk.next_id}`.
   - **Ссылка «Открыть документ целиком»:** ведёт на запрос `GET /api/documents/{doc_id}` и отображает полный текст документа `document.raw_text`.

## 5. Отправка вопроса и обработка ошибок

- **Эндпоинт:** `POST /api/chats/{chat_id}/messages`
- **Тело запроса:**
  ```json
  {
    "content": "В какой срок необходимо уведомить об отказе от договора?"
  }
  ```
- **Поведение интерфейса при отправке:**
  1. Поле ввода текста и кнопка отправки **блокируются (disabled)** до получения ответа или ошибки.
  2. В список сообщений добавляется оптимистичная плашка вопроса пользователя с индикатором ожидания (спиннером).
  3. По завершении запроса:
     - При успехе (`200 OK`): добавляется сообщение ассистента с чипами источников, поле ввода очищается и разблокируется.
     - При ошибке (`5xx`, `503 Service Unavailable`, таймаут сети):
       - Отобразить всплывающее уведомление (Toast) с описанием проблемы.
       - **Вопрос пользователя остаётся в поле ввода или в истории**, чтобы пользователю не пришлось набирать его заново.
       - Разблокировать поле ввода для повторной попытки.
